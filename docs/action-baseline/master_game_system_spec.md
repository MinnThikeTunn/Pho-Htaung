## 1. စာရွက်၏အလုပ်နှင့် သက်ရောက်မှု

ဤစာရွက်သည် အခန်းတိုင်းက မျှဝေသုံးမည့် စည်းမျဉ်းများ၊ ဂိမ်းပန်းတိုင်၊ progression၊ ငွေကြေး၊ save/retry နှင့် တည်ဆောက်စမ်းသပ်မည့်အစဉ်ကို သတ်မှတ်ရန်ဖြစ်သည်။ အခန်းတိုင်း၏နေရာချထားပုံနှင့် dialogue အပြည့်အစုံကို ဤနေရာတွင်မရေးပါ။

`chapter_1_revised_spec.md` revision 0.3 သည် technical handoff နှင့်ချိတ်ထားသည်။ ၎င်း၏ revision 0.2 geometry၊ movement နှင့် attack timings ကို မပြောင်းဘဲ အခန်း ၁ prototype baseline အဖြစ်ဆက်ထားသည်။ ဤ draft ကြောင့် မူလအခန်း ၂–၅ အလိုအလျောက်ပြောင်းပြီးသားမဟုတ်ပါ။ Approved ending direction ရှိသော်လည်း နောက်ဆုံးအခန်းအသေးစိတ် မရေးရသေးပါ။

သတ်မှတ်ချက်အဆင့်များ:

- **ဆက်ထိန်းမည့်အခြေခံ** — ဆွေးနွေးခဲ့သောကစားဟန်နှင့် အခန်း ၁ baseline မှယူထားသည်။
- **အတည်ပြုပြီး** — အသုံးပြုသူနှင့် တစ်ချက်ချင်းတိုင်ပင်၍ ရွေးထားသည်။ အခြားအကြံပြုချက်အားလုံးကိုပါ လက်ခံထားသည်ဟုမယူရ။
- **အကြံပြုချက်** — ယခုတင်ပြသောဆုံးဖြတ်ချက်။ အသုံးပြုသူလက်ခံပြီးသားဟု မယူရ။
- **တိုင်ပင်ရန်** — အဖြေမရမချင်း final implementation contract မဖြစ်ရ။
- **စမ်းသပ်ရန်** — စာရွက်ပေါ်ခန့်မှန်းချက်သာရှိပြီး playable validation လိုသည်။

Approved revision ရရှိပြီးနောက် master က shared policy ကိုပိုင်မည်၊ chapter spec က local layout/timing ကိုပိုင်မည်။ ကွဲလွဲချက်ရှိလျှင် conflict list ရေးပြီးပြင်မည်၊ နှစ်ဖိုင်လုံးကိုမပြင်ဘဲ တစ်ဖိုင်ကတစ်ဖိုင်ကို တိတ်တဆိတ် override မလုပ်ရ။

## 2. ဂိမ်း၏အနှစ်သာရ

**ဆက်ထိန်းမည့်အခြေခံ:** ဖိုးထောင်သည် အကြွေးရှင်များထံမှပြေးရင်း ရွှေမြို့တော်ရှိသည်ဟူသော ဦးကြီး၏စကားကိုယုံ၍ လိုက်လာသည်။ ဦးကြီးက ကူညီသလိုပြောနေသော်လည်း သူ၏စက်များသည် ဖိုးထောင်ကိုအန္တရာယ်ပေးနေသည်။ ဖိုးထောင်သည် အန္တရာယ်ကိုဖတ်၊ ရှောင်၊ ထိုစက်နှင့်ပစ္စည်းများကို ပြန်အသုံးချပြီး ရှေ့ဆက်ရသည်။

ကစားခြင်း၏အဓိကပျော်စရာသည် “ဦးကြီးလုပ်သောဒုက္ခကို ကိုယ့်အတွက်အသုံးဝင်အောင်ပြန်လှည့်ခြင်း” ဖြစ်သည်။ ဝှက်ထားသောအဖြေတစ်ခုကို ခန့်မှန်းရှာဖွေခြင်းသက်သက်မဖြစ်ရ။ ဤသည် design identity ဖြစ်ပြီး ကမ္ဘာတွင်မရှိဖူးသောဂိမ်းဖြစ်ကြောင်း အာမခံချက်မဟုတ်ပါ။

အခြေခံကစားစဉ်:

1. စက်၊ အန္တရာယ်နှင့် ထွက်ပေါက်အခြေအနေကိုကြည့်။
2. ကိုယ့်နေရာနှင့် လှုပ်ရှားချိန်ကိုရွေး။
3. အန္တရာယ်ကိုရှောင်၍ ပတ်ဝန်းကျင်ကိုပြောင်းလဲစေ။
4. ဖွင့်လာသောလမ်းကိုအသုံးချ၊ အပိုရွှေအတွက် အန္တရာယ်ထပ်ယူမယူဆုံးဖြတ်။
5. ထွက်ပေါက်ရောက်၊ ရလာဒ်သိမ်း၊ နောက်အခန်းသို့ဆက်။

ပစ်မှတ်ထားခံရခြင်းနှင့်ဘေးရှောင်ခြင်းတစ်မျိုးတည်းကို အခန်းတိုင်းတွင် ထပ်မလုပ်ရ။ အခန်းအသစ်သည် ကစားသူ၏ဆုံးဖြတ်ပုံကို ပြောင်းစေရမည်။ အန္တရာယ်ပစ္စည်း၏ပုံနှင့်အရောင်ကိုသာပြောင်းခြင်း မလုံလောက်ပါ။

## 3. Main objective နှင့် optional objective

**အတည်ပြုပြီး D03:** ဂိမ်း၏အဓိကအောင်မြင်မှုသည် ဦးကြီး၏ထောင်ချောက်များမှ အသက်ရှင်လွတ်မြောက်ခြင်းဖြစ်သည်။ သူ့လိမ်လည်မှုကိုဖော်ထုတ်သောဇာတ်သိမ်းနှင့်ချိတ်မည်။ ယူထွက်လာသောရွှေနှင့် အကြွေးပါဆပ်နိုင်လျှင် ပိုကောင်းသောဇာတ်သိမ်းရမည်။

လိုက်နာရမည့်အချက်များ:

- အခန်းကျော်ရန် ငွေမတောင်းရ။
- ရွှေလုံးဝမယူနိုင်လည်း main ending သို့ရောက်နိုင်ရမည်။
- အကြွေးမကျေလည်း “ဂိမ်းမပြီးနိုင်၊ အခန်းဟောင်းကို မဖြစ်မနေပြန်ကစား” မဖြစ်ရ။
- ရွှေစုခြင်းက ရလာဒ်နှင့် ဇာတ်သိမ်းအသေးစိတ်တွင် သက်ရောက်မှုရှိရမည်။
- ဦးကြီးလိမ်ထားသော ရွှေမြို့တော်အဆောက်အအုံသည် အတုဖြစ်နိုင်သော်လည်း ကစားသူသိမ်းထားသည့် currency ကို နောက်ဆုံးတွင် တန်ဖိုးသုညအဖြစ်မပြောင်းရ။

မူလ forced-death-only ending ကို အဓိကအောင်မြင်မှုအဖြစ်မသုံးတော့ပါ။ Final encounter ၏ mechanics၊ reveal အသေးစိတ်နှင့် အကြွေးဆပ်သည့်အချိန်/ပမာဏကို မသတ်မှတ်ရသေးပါ။

## 4. Scope နှင့် ကစားချိန်

**ဆက်ထိန်းမည့်အခြေခံ:** ပထမ target သည် desktop web၊ keyboard၊ 2D Burmese comic action-puzzle ဖြစ်သည်။ အခန်း ၁ တွင် 1280 × 720 logical world နှင့် fixed 60 Hz simulation ကိုသုံးသည်။ နောက်အခန်းများလည်း input နှင့် movement feel တူရမည်။

**အတည်ပြုပြီး D05:** 2D cartoon ပုံစံ။ Pixel art မဟုတ်ပါ။ Final character sheet၊ palette နှင့် animation artwork ကို မအတည်ပြုရသေးပါ။ Art မပြီးသေးခြင်းက ယာယီပုံဖြင့် prototype ရေးစမ်းခြင်းကို မတားရ။

**အတည်ပြုပြီး D01:** ပထမထုတ်ဝေမှုတွင် ပထမဆုံးကစားသူအတွက် retry ပါဝင်သော 10–20 မိနစ်အရွယ်ကို ရည်မှန်းမည်။ ဤအချိန်သည် အာမခံချက်မဟုတ်၊ အခန်းများပြီးမှတိုင်းတာရမည့် target ဖြစ်သည်။ လက်ရှိအခန်း ၅ ခန်းသည် content အကြမ်းဖျဉ်းသာဖြစ်ပြီး တစ်ခန်းချင်းတာဝန်ကိုဆက်စစ်ရမည်။

ကျွမ်းကျင်သူ၏ရှင်းပြီးသားလမ်းကြောင်းက ပိုတိုနိုင်သည်။ Dialogue၊ attack စောင့်ချိန်နှင့် အတင်းသေခိုင်းခြင်းတို့ဖြင့် မိနစ်ပြည့်အောင်မဆွဲရ။

အခန်း ၁ ရှိ ပထမကစားချိန် 1–3 မိနစ်၊ ကျွမ်းကျင် direct clear 8–20 စက္ကန့်ဆိုသော targets ကို ယခုမပြောင်းပါ။ တစ်ခန်းတည်း၏အချိန်ကို ငါးဆမြှောက်၍ campaign အရှည်အတိအကျဟုမတွက်ရ။

30–60 မိနစ်အထိချဲ့ခြင်းကို ယခုပထမထုတ်ဝေမှု၏ target အဖြစ်မသုံးပါ။ ကစားချိန်မပြည့်လျှင် စောင့်ချိန်တိုးမည့်အစား တကယ်ကစားရသောစိန်ခေါ်မှု လုံလောက်မလုံလောက်ကိုစစ်ရမည်။

## 5. Player နှင့် interactions

**ဆက်ထိန်းမည့်အခြေခံ:**

- A/D သို့မဟုတ် arrow keys ဖြင့် ဘယ်/ညာ၊ Space ဖြင့်ခုန်၊ Esc pause၊ R hold ဖြင့်လက်ရှိ attempt ပြန်စ။
- Player body၊ gravity၊ jump နှင့် horizontal movement ကို အခန်းတစ်ခန်းချင်းအကြောင်းမဲ့မပြောင်းရ။ အခန်း ၁ constants သည် ပထမ shared baseline ဖြစ်သည်။
- E သည် အခန်း ၁ တွင်သာ သတ်မှတ်ပြီးသား taunt ဖြစ်သည်။ နောက်အခန်းတွင် E က ဘာလုပ်မည်ကို သီးခြားရေးရန်လိုသည်။ ခလုတ်တစ်ခုက မရှင်းပြဘဲ အဓိပ္ပာယ်ပြောင်းမသွားရ။
- အခန်း ၁ တွင် တွန်းရန် သီးခြားခလုတ်မလို။ ဤနည်းကိုသုံးသော နောက်အခန်းများတွင်လည်းတူရမည်။
- သရဲဝင်ပူးခြင်း၊ magic command၊ double jump၊ dash နှင့် combat skill tree တို့သည် ယခု scope မဟုတ်။

**အကြံပြုချက်:** ပထမ version တွင် အမြဲဖွင့်ထားရသော drag-and-drop inventory မထည့်သေးရန်။ ဇာတ်ကောင်၏လွယ်အိတ်နှင့်ကွမ်းသီးညှပ်ကို identity အဖြစ်ထားနိုင်သော်လည်း မူလအခန်း ၂–၄ puzzle recipes ကို လက်ခံပြီးသား shared system ဟုမယူရ။

အခန်း ၁ ၏ `ownedTools` နှင့် original `inventory` သည် လက်ရှိ compatibility fields သာဖြစ်သည်။ ဆိုင်နှင့်အသုံးပြုနိုင်သော tools အမှန်တကယ်ရှိပြီးသားမဟုတ်ပါ။ အပြီးသတ်အခန်းအကြမ်းဖျဉ်းတွင်လိုအပ်မှ ထပ်သတ်မှတ်ရန်။

## 6. Fairness၊ ဟာသနှင့် ရလာဒ်

**ဆက်ထိန်းမည့်အခြေခံ:**

- ဦးကြီး၏စကားကလိမ်နိုင်သည်။ ထိခိုက်မည့်နေရာနှင့် အချိန်ပြသော gameplay warning ကမလိမ်ရ။
- လမ်းနည်းအသစ်သည် စည်းမျဉ်းနှင့်ကိုက်လျှင်ခွင့်ပြုရမည်။ Walkthrough အတိုင်းလုပ်ပြီးမှသာ exit ဖွင့်ခြင်း မလုပ်ရ။
- စမ်းသပ်ဖို့မဖြစ်မနေသေရခြင်း မလိုရ။ အန္တရာယ်ကိုနားလည်ပြီးရှောင်နိုင်ရမည်။
- ပစ္စည်းနေရာမှားခြင်းကြောင့် အနိုင်ရနိုင်သောနည်းလမ်းအားလုံး ပျောက်မသွားရ။ Recovery rule ကိုအခန်းတိုင်းက သက်သေပြရမည်။ R restart ရှိရုံဖြင့် ကောင်းမွန်သော recovery ရှိသည်ဟုမယူရ။
- Voice/dialogue က control၊ warning သို့မဟုတ် retry ကိုမနှောင့်ယှက်ရ။ Repeat lines ကိုလျှော့ရမည်။ အသံပိတ်ထားလည်း gameplay အပြည့်နားလည်နိုင်ရမည်။
- Burmese font နှင့် combining characters ကိုမှန်ကန်စွာပြရန်။ Flash/shake ကိုပိတ်နိုင်ရန်။

အခန်း ၁ တွင် death source၊ collision order နှင့် death priority ကို local spec အတိုင်းလိုက်နာမည်။ နောက်အခန်းအန္တရာယ်များကို မစမ်းသပ်ဘဲ အတူတူသေစည်းမျဉ်းဟုမခန့်မှန်းရ။

## 7. ငွေကြေး — ပမာဏထက် အသုံးဝင်မှုကိုအရင်ဆုံးဖြတ်ရန်

**အတည်ပြုပြီး D02:** ပထမ version တွင် ဆိုင်မထည့်သေးပါ။ နောက်ပိုင်းဆိုင်ထည့်ရန် ရည်ရွယ်ချက်ရှိသည်၊ ဆိုင်ကိုအပြီးဖယ်ထားခြင်းမဟုတ်ပါ။ လက်ရှိရွှေ၏အဓိကသက်ရောက်မှုသည် အကြွေးဆပ်နိုင်သောပိုကောင်းသည့်ဇာတ်သိမ်းဖြစ်သည်။ Currency တစ်မျိုးတည်းသုံးရန် အကြံပြုချက်ကိုဆက်ထားသည်။

အကြောင်းရင်း: အပိုရွှေယူခြင်း၏ စွန့်စားမှုကို ဆက်ထိန်းနိုင်ပြီး အကြွေးပြေးဇာတ်လမ်းနှင့်ချိတ်သည်။ Tools ဝယ်မှနောက်အခန်းကောင်းကောင်းကစားနိုင်ခြင်း၊ ငွေကုန်သဖြင့်ပြန်စုရခြင်းနှင့် tool အမျိုးမျိုးအတွက် level balance ပွားလာခြင်းကို မလိုအပ်သေးပါ။ ယင်းသည် အခန်းကစားဟန်ကိုပျော်စေကြောင်း သက်သေမဟုတ်ပါ။

နောက်ပိုင်းဆိုင်အတွက် ပြင်ဆင်ထားရမည့်နယ်နိမိတ်: ရလာသောငွေမှတ်တမ်း၊ လက်ကျန်ငွေနှင့် ဝယ်ယူမှုမှတ်တမ်းကို သီးခြားထားနိုင်ရန်။ ယခု shop UI၊ ပစ္စည်းစနစ်နှင့် ဈေးနှုန်းများကို မတည်ဆောက်ရ။ ဆိုင်အမျိုးအစားနှင့် ဘယ် version တွင်ထည့်မည်ကိုလည်း မရွေးရသေးပါ။

ဆိုင်အသေးစိတ်မစမီ အောက်ပါအချက်များထပ်ရေးရမည်:

- ဘာပစ္စည်းကိုဝယ်နိုင်သလဲ၊ ဘယ်အခန်းမှစ၍ အသုံးဝင်သလဲ။
- ပစ္စည်းမဝယ်ထားသူလည်း အခန်းအားလုံးရှင်းနိုင်သလား။
- ငွေသုံးလိုက်ခြင်းက အကြွေးကျေအဆုံးသတ်ကို အပြီးတိုင်ဆုံးရှုံးစေသလား၊ စေမည်ဆိုလျှင် မဝယ်မီပြထားသလား။
- ဝယ်ပြီးသား tool ပါသူနှင့်မပါသူ၏ records နှိုင်းယှဉ်မှုက တရားမျှတသလား။
- ဝယ်ပစ္စည်းသည် optional နည်းလမ်းဖွင့်ခြင်းလား၊ တန်းတူလမ်းကိုသာပိုလွယ်စေခြင်းလား။

Item prices ကိုဆိုင်ဒီဇိုင်းမရှိဘဲမသတ်မှတ်ရ။ အကြွေးပမာဏနှင့် အခန်း ၂–၅ rewards ကို earning/replay rule နှင့် chapter content budget စစ်ပြီးမှသတ်မှတ်ရမည်။ လက်ရှိအခန်း ၁ max 15 ကို campaign total ဟုမယူရ။ နောင်ဆိုင်ထည့်ရာတွင် limited currency နှင့် အကြွေးပန်းတိုင် မဆန့်ကျင်ကြောင်း economy ကိုပြန်စစ်ရမည်။

### 7.1 အတည်ပြုပြီး D04 — Replay earning rule

အခန်းတစ်ခန်းကို ပြန်ကစားရာတွင် ယခင်အောင်မြင်စွာသိမ်းခဲ့သောအများဆုံးထက် ပိုကောက်နိုင်သောပမာဏကိုသာ ထပ်ပေးရန် အသုံးပြုသူကအတည်ပြုထားသည်။ တစ်ခန်း၏စုစုပေါင်းရနိုင်သည့်ပမာဏအထိသာရမည်။ ဤဆုံးဖြတ်ချက်က သေချိန်ငွေဆုံးရှုံးမှု၊ practice reward နှင့် အကြွေးဆပ်သည့်နည်း အသေးစိတ်အားလုံးကိုပါ အတည်ပြုထားခြင်းမဟုတ်ပါ။

လက်ရှိအခန်း ၁ baseline မှ ဆက်ထားသောဆက်စပ်စည်းမျဉ်းများ:

- လက်ရှိ attempt တွင်ကောက်ထားသည့်ငွေနှင့် exit ပြီးသိမ်းထားသောငွေကို သီးခြားပြမည်။
- သေခြင်း/လက်ရှိအခန်း restart တွင် unbanked attempt coins ကို reset လုပ်မည်၊ banked coins ကိုမလျော့စေ။
- အခန်းတစ်ခန်း၏ canonical version ကို ပိုများသောငွေနှင့်အောင်မြင်မှ ယခင်အများဆုံးထက်ပိုလာသောငွေကိုသာ ထပ်သိမ်းမည်။
- အခန်း ၁ ဥပမာ: 5 → 15 → 15 clear လျှင် credit +5 → +10 → +0 ဖြစ်မည်။
- Practice variants က records သာပေးပြီး ငွေမပွားစေရ။
- ငွေသုံးခြင်းရှိလာလည်း best-earned record ကိုမလျော့စေရ။

Chapter တစ်ခုအတွက် `credit = max(0, collectedThisClear - previousBest)` ဖြစ်ပြီး အောင်မြင်ပြီးနောက် `newBest = max(previousBest, collectedThisClear)` ဖြစ်သည်။ Settlement ကို duplicate မဖြစ်စေရ။

Campaign total obtainable = အခန်း canonical maxima အားလုံးပေါင်း။ အကြွေးကျေအဆုံးသတ်ကိုထည့်လျှင် debt target သည် ကစားသူအမှန်တကယ်ရနိုင်သောပမာဏနှင့်ကိုက်ရမည်။ ရွှေအားလုံးရမှသာကျေစေမည်လားဆိုသည်ကို ပမာဏတင်မဟုတ်ဘဲ difficulty ဆုံးဖြတ်ချက်အဖြစ်စစ်ရမည်။

ယခုအဆင့်တွင် ဆိုင်၊ အကြွေးဆပ် transaction၊ ending payout code တို့ကို မရေးရ။

## 8. State ownership၊ save နှင့် retry

**ဆက်ထိန်းရန်အကြံပြုချက်:**

| အဆင့် | ပိုင်သောအချက်များ | Retry တွင် |
|---|---|---|
| Campaign | campaign ID၊ unlocked chapters၊ completed chapters၊ banked gold၊ chapter best gold၊ deaths၊ successful records | မဖျက် |
| Chapter session | ဝင်လာသည့် chapter/mode၊ session deaths၊ campaign မှလာသလား practice မှလာသလား | session deaths ဆက်တိုး |
| Attempt | player/world/AI၊ pickups၊ collected gold၊ elapsed time၊ attempt ID၊ completion latch | initial snapshot အပြည့်ပြန်ထား |
| Settings | audio၊ shake၊ hints စသည့်ရွေးချယ်မှု | မဖျက် |

- အခန်းတစ်ခန်း၏ ပထမ canonical clear က နောက်အခန်းကိုဖွင့်မည်။ ငွေအနည်းဆုံး၊ practice clear သို့မဟုတ် speed grade မတောင်းရ။
- ပြီးသားအခန်းကို replay လုပ်ခြင်းက နောက်အခန်း unlock နှင့် story progress ကိုမဖျက်ရ။
- Pause/hidden tab တွင် active simulation နှင့် clocks ရပ်မည်။ Resume တွင်ကပ်နေသော key inputs ကိုရှင်းမည်။
- အခန်း ၁ retry သည် 0.90 s နှင့်အပြည့် snapshot reset ကိုလိုက်နာမည်။ နောက်အခန်းများတွင်လည်း မြန်ဆန်သော retry ကိုသုံးရန်၊ reset အစီအစဉ်သည် chapter-local ဖြစ်မည်။
- New Game သည် retry မဟုတ်။ ရှိပြီးသား campaign ကိုဖျက်မည့်အပြုအမူအတွက် ရှင်းလင်းသောအတည်ပြုချက်လိုမည်။

**အကြံပြု save scope:** browser local save တစ်ခု။ Cloud/account/network leaderboard မပါ။ အောင်မြင်သည့်အခန်း boundary၊ currency settlement၊ unlock နှင့် settings ကိုသိမ်းမည်။ Reload ပြီးနောက် လက်ရှိအခန်းအစမှဆက်မည်၊ လေထဲခုန်နေရာကဲ့သို့ mid-attempt physics ကိုမသိမ်းသေးပါ။

Wallet၊ best earned နှင့် settlement receipt ကို တစ်ခုတည်းသော save update အဖြစ်ရေးရန်။ Save ပျက်/မရလျှင် သိမ်းပြီးဟုမပြောရ၊ session ကို memory ဖြင့်ဆက်နိုင်သော်လည်း reload တွင်ပျောက်နိုင်ကြောင်းပြရန်။ Browser local data ဖျက်လျှင် save ပျောက်နိုင်ကြောင်းလည်း ရှင်းပြရမည်။ Storage schema နှင့် migration ကို gameplay အတည်ပြုပြီးမှအသေးစိတ်ရေးမည်။

## 9. အခန်းများ၏တာဝန် — အပြီးသတ် level design မဟုတ်

| အခန်း | ယခုသိထားသောအလုပ် | မပြီးသေးသောအချက် |
|---|---|---|
| 1 — ကျောက်တုံးချစက် | အန္တရာယ်ကို အသုံးဝင်သောပစ္စည်းအဖြစ်ပြောင်းသုံးတတ်စေ။ အသေးစိတ် baseline ရှိ | Actual movement၊ routes၊ repeat playtest |
| 2 — ရေနွေးငွေ့/မီးဖိုပတ်ဝန်းကျင် | အခန်း ၁ ၏ကျောက်တုံးချသည့် rhythm ကိုမကူးဘဲ ထိန်းထားရသောစက်နှင့် လွတ်မြောက်ချိန်ဆုံးဖြတ်မှုကိုစမ်းရန် အကြံပြုထား | Steam direction/control၊ objective၊ geometry၊ rewards မသတ်မှတ်ရသေး |
| 3 — ချိန်ခွင်ပတ်ဝန်းကျင် | မူလအပြင်အဆင်ကိုယူနိုင်၊ ယခုအဆင့်တွင် gameplay ခွင့်ပြုပြီးသားမဟုတ် | Core loop နှင့်ကိုက်သောဆုံးဖြတ်ချက်ရှိမရှိ အရင်စစ်ရန် |
| 4 — သေတ္တာ/သိုလှောင်ခန်းပတ်ဝန်းကျင် | မူလဇာတ်လမ်းမှယူနိုင်၊ keyhole chili recipe ကို အလိုအလျောက်မဆက်ခံ | Action-puzzle identity နှင့်ကိုက်သော concept လို |
| 5 — ရွှေမြို့တော်အမှန်နှင့် ထွက်ပေါက် | လွတ်မြောက်ခြင်းက main win၊ အကြွေးကျေလျှင်ပိုကောင်းသော ending | Final challenge၊ reveal နှင့် ending လုပ်ပုံရေးရန် |

အခန်း ၂ steam/turbine/တံခါးတုံးခံအကြံသည် ဆွေးနွေးခဲ့သော candidate သာဖြစ်ပြီး final spec မဟုတ်။ အခန်း ၃–၄ တွင်လုပ်စရာအတိအကျမရှိသေးကြောင်းကို စကားလှဖြင့်ဖုံးမထားရ။

အခန်းတစ်ခန်းအသစ်ကို လက်ခံမီ “ယခင်နည်းကို ဘာကြောင့်အတိုင်းအတာမပြောင်းဘဲမသုံးနိုင်တော့သလဲ၊ ဘာအသစ်ဆုံးဖြတ်ရသလဲ” ဟူသောမေးခွန်းကို ရှင်းရှင်းဖြေနိုင်ရမည်။ မဖြေနိုင်လျှင်အခန်းအသစ်ထည့်ခြင်းထက် ရှိပြီးသားကိုတိုအောင်ထားခြင်းက ပိုကောင်းနိုင်သည်။

## 10. ဆောက်မည့်အစဉ်နှင့် စမ်းသပ်တံခါးများ

1. D01–D05 နှင့်လက်ရှိအခန်း ၁ baseline ကိုလိုက်နာ၍ technical/asset/test contracts ဖတ်။ ကျန်သောအဓိကဆုံးဖြတ်ချက်လိုလျှင် တစ်ခါလျှင်တစ်ခုစီတိုင်ပင်။
2. Implementation လုပ်ရန်အသုံးပြုသူညွှန်ကြားလျှင် **Chapter 1 ကိုအရင်** graybox prototype ဆောက်။ နောက်အခန်း ၂–၅ concepts အားလုံးပြီးမှစရန် မစောင့်ရ။ Final art/အသံ/sိုင် မလိုသေး။
3. Chapter 2 မရှိသေးသော build တွင် safe exit link မှ prototype result panel သို့ရောက်ရမည်။ Chapter 2/ending ကိုမထင်မှတ်ဘဲဆက်မရေးရ။
4. Chapter 1 ကိုမညွှန်ပြဘဲစမ်း၍ နားလည်မှု၊ input feel၊ waiting၊ route dominance နှင့် ပြန်စမ်းချင်စိတ်ကိုစစ်။ အထောက်အထားဖြင့်သာ baseline ကိုပြင်။
5. အခြေခံပျော်စရာတည်ငြိမ်မှ အခန်း ၂–၅ တာဝန်၊ ဆုံးဖြတ်ချက်အသစ်၊ ခန့်မှန်းကစားချိန်နှင့် reward budget ကိုအကြမ်းချ။ Campaign total နှင့်အကြွေးပမာဏကိုထိုအချိန်မှချိန်။
6. Chapter 2 အသေးစိတ်ရေး/ဆောက်။ Shared rule ပြင်လျှင် ဘယ်အခန်းများကိုထိသည်ဟုရေးပြီး regression စစ်။

စမ်းသပ်ရာတွင် clear ဖြစ်ရုံကို fun ဟုမသတ်မှတ်ရ။ ကစားသူ ၃ ကြိမ်ကြိုးစားပြီးနောက် နည်းလမ်းပိုနားလည်လာသလား၊ နည်းကွဲစမ်းချင်သလား၊ အမှားကြောင့်သေလား မမြင်နိုင်လို့သေလား၊ တူညီလုပ်ရပ်ကိုစောင့်ပြီးထပ်လုပ်နေရသလားဆိုသည်ကိုမှတ်ရန်။

## 11. ဆုံးဖြတ်ချက်မှတ်တမ်းနှင့် ကျန်သောအလုပ်

| ID | မေးခွန်း | အတည်ပြုထားသောအဖြေ | ဆက်သတ်မှတ်ရမည့်အရာ |
|---|---|---|---|
| D01 | ပထမဂိမ်းအရှည် | Retry ပါ ပထမကစား 10–20 မိနစ်ဝန်းကျင် | Chapter content budget နှင့် actual duration test |
| D02 | ဆိုင်နှင့် ငွေအသုံး | ပထမ version တွင်ဆိုင်မပါ၊ နောက်ပိုင်းထည့်ရန်ရှိ၊ လက်ရှိရွှေကအကြွေးဆပ်အဆုံးသတ်ကိုသက်ရောက် | Debt amount၊ chapter rewards၊ future shop design |
| D03 | ဇာတ်သိမ်း | လွတ်မြောက်ခြင်းက main win၊ အကြွေးပါဆပ်နိုင်လျှင်ပိုကောင်းသောဇာတ်သိမ်း၊ ငွေနည်းလည်းဂိမ်းပြီးနိုင် | Final challenge၊ အကြွေးဆပ်သည့်အချိန်/ပမာဏနှင့် reveal |
| D04 | အခန်းဟောင်း replay မှငွေရပုံ | ယခင်အများဆုံးထက် ပိုကောက်နိုင်သောပမာဏသာထပ်ပေး၊ တစ်ခန်း၏ total cap မကျော် | အခန်းတိုင်း၏ coin maxima နှင့် စုစုပေါင်း economy balance |
| D05 | ရုပ်ပုံပုံစံ | 2D cartoon | Character sample၊ palette၊ final asset approval |

D01–D05 ကို အသုံးပြုသူအတည်ပြုထားသည်။ အခြားအကြံပြုချက်အားလုံးကို အလိုအလျောက်အတည်ပြုပြီးဟုမယူရ။ လက်ရှိတည်ဆောက်ရမည့်အပိုင်းသည် အခန်း ၁ prototype ဖြစ်သည်။ နောက်အခန်းများနှင့် campaign economy အပြည့်သည် implementation-ready မဟုတ်သေးသော်လည်း ထိုအရာများကြောင့် အခန်း ၁ prototype ကိုမပိတ်ထားရ။
